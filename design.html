Design

Hardware centers on a Turtlebot3 mobile base with a custom mount and delivery box, paired with a UR7e manipulator and RGB-D sensing. Cone color encodes hazard type; colored blocks are the “tools” used to neutralize each hazard. An ArUco marker on the mount supports precise handoff poses for the arm.

High-level workflow

  • Turtlebot: start docked, run auto-mapping / exploration, detect and track hazards, return to dock, and signal the arm when a specific block color is required.
  • UR7e: listen for Turtlebot requests, pick the requested colored block, place it on the mount using ArUco tag 10 for alignment, and publish a completion signal.
  • Turtlebot: after completion, navigate to the confirmed cone and wait for human pickup of the delivered mitigation payload.

Multi-robot coordination

Both robots originally published a base_link frame, which broke RViz when run together. Namespacing alone proved brittle with existing assets, so the team adopted ROS 2 Domain Bridge with separate domain IDs and a YAML bridge to relay selected topics, giving stable transforms and communication across platforms.
