Implementation

Launch and architecture

launch/system.launch.py is the “big green button”: it brings up mapping, perception, navigation, and mission management for the Turtlebot side, exposes tuning parameters, and supports sim versus real and manual versus auto-map modes from the command line.

Auto-mapping

After considering explore-lite, the team implemented custom frontier exploration with a bounding polygon. Occupancy grids from SLAM Toolbox are masked and morphologically filtered; connected components label unknown frontiers. Frontiers are scored by mass, distance from the robot in the map frame, and size before sending goals through Nav2’s action server. A finite state machine sequences map iteration, frontier filtering, and discovery.

Perception and hazard pipeline

Cone colors are segmented in HSV with OpenCV, using morphological opening and closing before contour extraction. The hazard detector fuses image bearings with LiDAR clusters: an initial polar-domain linear clusterer worked in simulation but failed under real sensor noise, so the pipeline was upgraded with agglomerative merging of small clusters. Detections are matched to clusters (moving from greedy per-detection assignment toward a scored matrix formulation) and converted to map coordinates for hazard messages.

A hazard tracker merges repeated detections by color within a radius, confirms tracks after three consistent observations, and publishes smoothed poses for the Mission Manager and RViz.

Mission Manager

The Mission Manager is the Turtlebot’s orchestrating FSM, sequencing auto-mapping, navigation to frontiers, cone handling, docking, UR7e synchronization, and user handoff. It communicates with Nav2 using patterns tuned for the project’s navigator rather than only the basic tutorials.

UR7e application graph

  • Perception: colored block poses from depth, constant wrist→camera transforms, ArUco detections from ros2_aruco.
  • Planning / control: IK and motion planning libraries, MoveIt services (/compute_ik, /plan_kinematic_path), and follow_joint_trajectory to the UR driver, plus gripper toggling.
  • Integration: main grasp node coordinates block poses and markers, publishes readiness on /scout/package_ready, and follows the launch recipe: RealSense + MoveIt, a TF stabilization delay, then four application nodes.
